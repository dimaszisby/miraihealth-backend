## Summary

- **Unit tests:** 27 suites — covers every feature’s domain/application/infrastructure layer via mocks. No suite under `features/**` currently hits a live DB or HTTP app.
- **Integration tests:** 13 suites — API smoke suites plus the repository-level suites (`MetricRepoSequelize`, `MetricReadRepoSequelize`, `MetricSettingsRepositorySequelize`, `MetricLogRepoSequelize`, `VisualizationReadRepoSequelize`, `UserRepositorySequelize`) that now exercise the real DB.
- **Patterns & gaps:**
  - Documentation assumed application/infrastructure tests under `features/**` were integration tests; in practice they are in-memory and behave like classic unit tests.
  - Integration coverage is still concentrated in API smoke suites, but Phase 2 repo-level suites (metrics) are beginning to land. Remaining repositories (auth, metric settings, analytics) still need real DB coverage.
  - Static/contract layers already live outside `__tests__/`, so the migration mainly needs to carve `unit/` vs `integration/` trees for clarity.
